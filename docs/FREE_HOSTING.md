# Free hosting for development & stakeholder demos

Until stakeholders approve a production launch, run the CRM at **no cost** on:

| Piece | Service | Free tier (check current limits on their sites) |
|---|---|---|
| App (web + background worker) | **Render** free web service (Docker) | No credit card. 512 MB RAM, sleeps after ~15 min without traffic, ~1 min to wake. |
| Database | **Neon** free Postgres | No credit card. Small storage quota (plenty for demo data); compute auto-suspends when idle. |
| Files (uploaded documents) | Stored **inside Postgres** (`STORAGE_DRIVER=database`) | No extra account needed. |

Free tiers don't offer a separate worker container or a persistent disk, so this mode:

- runs the background worker **inside the web process** (`RUN_WORKER_IN_WEB=true`, see `src/instrumentation.ts`);
- stores uploaded files in the `StoredFile` table (`STORAGE_DRIVER=database`);
- applies migrations and the (idempotent) seed at every start (`scripts/start-web.sh`).

The code is the same one that will run in production; only environment variables differ.

> **Demo data only.** Don't put real client or KYC data on the free tier. Demo mode lets all demo users sign in with one shared password, and the free tiers come with no backups or uptime guarantees (Data Privacy Act, RA 10173).

## 1. Database: Neon (≈5 minutes)

1. Sign up at **neon.tech** (you can use your GitHub account).
2. **Create project**: name `citrineland-crm`, Postgres **16**, region **AWS Asia Pacific (Singapore)**.
3. On the project dashboard, open **Connect** and copy the connection string. **Turn connection pooling off** (use the *direct* connection, which Prisma migrations need). It looks like:
   `postgresql://neondb_owner:…@ep-xxxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`

## 2. App: Render (≈15 minutes, mostly the first build)

1. Sign up at **render.com** with GitHub and allow Render to access the `Citrineland_CRM` repository (it's private).
2. **New → Blueprint**, pick the repository and the branch with the code (currently `claude/eloquent-noether-rhkp5y`, or `main` once merged). Render reads `render.yaml` from the repo root.
3. Render asks for the values marked "sync: false":
   - `DATABASE_URL`: the Neon connection string from step 1.
   - `BOOTSTRAP_ADMIN_PASSWORD`: a strong password. In demo mode **all demo users** sign in with it, so share it only with the people attending the demo.
   - The three `AUTH_MICROSOFT_ENTRA_ID_*` values: **leave blank** for now (see section 4).
4. Click **Apply**. The first Docker build takes about 10 minutes. When it's live, open `https://citrineland-crm.onrender.com` (Render shows the exact URL), then check `…/api/health`.

`AUTH_SECRET` and `ENCRYPTION_KEY` are generated by Render, and `APP_URL`/`AUTH_URL` are taken automatically from Render's public URL.

## 3. Sign in for the demo

| Who | Email | Password |
|---|---|---|
| Admin | `admin@citrineland.test` | your `BOOTSTRAP_ADMIN_PASSWORD` |
| Sales Manager | `sales.manager@citrineland.test` | same |
| Marketing Manager | `marketing.manager@citrineland.test` | same |
| BNG Staff | `bng.staff@citrineland.test` | same |

Each role sees its own dashboard and menus, which shows the permission model well in a demo. All seeded data is fictional (two developments, brokers, ~40 leads, 10 transactions with payments and commissions).

### Before presenting

- **Wake it up 2–3 minutes early.** Free Render services sleep after about 15 minutes without traffic, and the first request then takes about a minute. Background jobs (hold expiry, automations, reminders) only run while it's awake, which is fine for a demo.
- A redeploy or restart keeps all data (it's in Neon). Uploaded files are kept too, because they're in the database.

## 4. Optional: Microsoft 365 in the demo

SSO and Outlook features (send email, email capture, calendar) need the Entra app registration from `docs/MICROSOFT_SETUP.md`. For the demo, add a second redirect URI to it:
`https://<your-app>.onrender.com/api/auth/callback/microsoft-entra-id`
Then fill in the three `AUTH_MICROSOFT_ENTRA_ID_*` variables in Render → Environment and redeploy. Without them, the app simply shows "Microsoft 365 not configured" and password login is used.

## 5. Day-to-day development

- **Every push to the deployed branch redeploys automatically** (`autoDeploy: true`). Migrations run on start.
- **Reset demo data:** in Neon, create a fresh database or branch, update `DATABASE_URL` in Render, and redeploy. The seed recreates everything.
- **Local development** stays free as well: see the README (`npm run dev` + `npm run worker` against a local Postgres).
- **Logs:** Render → your service → Logs.

## 6. Going to production later

When the go-signal comes, follow `docs/DEPLOYMENT.md` (DigitalOcean Droplet + Managed PostgreSQL + Spaces) and change only configuration:

| Variable | Free demo | Production |
|---|---|---|
| `RUN_WORKER_IN_WEB` | `true` | `false` (separate `worker` container) |
| `STORAGE_DRIVER` | `database` | `spaces` (with `SPACES_*`) |
| `DEMO_PASSWORD_LOGIN` | `true` | `false` |
| `SEED_DEMO` / `SEED_ON_START` | `true` | `false` (seed once without demo data) |
| `DATABASE_URL` | Neon | DO Managed PostgreSQL (fresh database; don't carry demo data over) |

No code changes are needed.
